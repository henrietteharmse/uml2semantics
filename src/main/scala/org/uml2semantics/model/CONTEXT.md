# Context: model

The internal vocabulary for describing a UML class diagram, independent of input format (TSV/XMI) and output format (OWL/SHACL). Everything here lives in `org.uml2semantics.model` and its `cache` subpackage. Readers construct these objects through builders; writers consume them.

## Glossary

- **Class identity** (`UMLClassIdentity`) — how a class is known: an optional *name*, an optional *curie*, plus the *ontology prefix* used to mint an IRI when only a name is present. At least one of name or curie must be present; having both is the fully *enriched* form.
- **Name** (`UMLClassName`, `UMLAttributeName`) — a plain UML identifier. Must not contain a colon and must not be blank. A name mints its IRI under the ontology prefix.
- **Curie** (`Curie`) — a compact URI of the form `prefixName:reference` (W3C CURIE spec). Only valid when its prefix name is a configured *prefix namespace*. A curie resolves to an IRI by prefix expansion, bypassing ontology-prefix minting — this is how classes and attributes are mapped onto external vocabularies (e.g. `schema:Person`).
- **Name-or-curie rule** — an identifier string containing `:` is interpreted as a curie; otherwise as a name (`withNameOrCurie`). This is why names may not contain colons.
- **Enrichment** — a later input source supplying the missing half of an identity (e.g. class `Person` later gains curie `schema:Person`). The caches merge the old entry into the enriched one field-by-field: non-empty older values (definition, attribute type, multiplicity) are kept when the newer build leaves them empty, the children of a class are added to (see *class merge*), and attributes still pointing at the old class identity are migrated (`AttributeCache.updateClassIdentity`). Enrichment is the mechanism behind the `--overrides` precedence between TSV and XMI.
- **Class merge** — a class arriving at `ClassCache` is merged with the earlier build of the same class whether or not it gains a half: under the same identity, or under either half when it has both. A definition the newer build states wins, and a blank one is taken from the earlier build. Children are added to: the class keeps the generalization sets of the earlier build beside those of the newer one, so no source can take away a child another source gave, in whichever order the sources are read. So a TSV row naming an XMI class by name alone adds to it instead of emptying it. The children a source gives form a generalization set of their own; a TSV child added to a class with a complete XMI generalization set does not join that set. See *reference follows identity* for a child that gains a curie afterwards.
- **Reference follows identity** — a generalization set records the identity each child had when it was built, and an attribute typed by a class or an enumeration records that classifier as it was when the attribute was built. Neither record is rewritten when the classifier later gains the other half of its identity. Instead the caches look the reference up again whenever they hand out a class (`ClassCache`) or an attribute (`AttributeCache.getAttributes`), so a generalization and the range of a property follow the classifier to the IRI it ends up with. Anything that reads the model reads it through the caches, and so never sees the older identity. Attributes differ on purpose: a later attribute of the same identity replaces the earlier one whole, and only gaining a curie merges (rule 17 of `docs/specs/xmi-associations.md`).
- **Ontology prefix** — the `PrefixNamespace` of the ontology being generated (CLI flag `-p`). Used to mint IRIs for name-only identities.
- **Prefix namespace** (`PrefixNamespace`) — a prefix name bound to a prefix IRI, registered in a global prefix map. `xsd`, `rdf`, `rdfs`, `owl` are predefined; others come from CLI flags `-p` and `-x`.
- **IRI minting** — for a class name: `<ontology-prefix-iri>/Name` (no extra `/` if the prefix IRI already ends in `/` or `#`). For an attribute name: `<ontology-prefix-iri>/ClassLabel#attributeName` — the class label as path segment, `#` as fragment separator. Curies expand directly and take precedence. An enumeration mints as a class does. A name-only enumeration value mints as an attribute does, with the label of its enumeration in place of the class label: `<ontology-prefix-iri>/EnumerationLabel#valueName`. A value holds no reference to its enumeration, so its IRI is asked of the enumeration (`UMLEnumeration.getValueIRI`). A value IRI cannot collide with an attribute IRI, because a class and an enumeration never share a label. See also *safe value IRI*.
- **Labeled IRI** (`LabeledIRI`) — anything carrying both an IRI and a human-readable label. The label prefers the name over the curie.
- **Attribute identity** (`UMLAttributeIdentity`) — an attribute's name/curie scoped by the identity of its owning class. Attributes are always class-scoped; there is no global attribute namespace.
- **Attribute type** (`UMLAttributeType`) — one of: a *supported data type* (`UMLXMLDataType`), a class in the diagram (`UMLClassType`), an enumeration in the diagram (`UMLEnumerationType`), or a curie denoting an external class (`CurieBasedUMLClassAttributeType`). A type string resolves in this order: supported-datatype curie → already-cached class → already-cached enumeration → curie → a new placeholder class built on the fly. The enumeration step precedes the curie step so that the curie of a known enumeration is not taken for an external class.
- **Enumeration** (`UMLEnumeration`) — a UML enumeration: an identity, an optional definition, and its *values*. Its identity (`UMLEnumerationIdentity`) has the same two halves as a class identity and follows the same *name-or-curie rule*.
- **Enumeration value** (`UMLEnumerationValue`) — a UML enumeration literal: a name and/or curie and an optional definition. A value is held *inside* its enumeration rather than cached beside it. That is what scopes its name: `Other` in two enumerations is two values. *Avoid*: literal, named value — the CLI flag and the TSV file call it a value.
- **Enumeration enrichment** — an enumeration arriving at the cache is merged with whatever is already cached under either half of its identity: a half or a definition the newer one leaves out is kept, and the values of both are combined, a value known to both being merged the same way. A row carrying both a name and a curie can therefore tie a name-only and a curie-only enumeration into one.
- **Safe value IRI** — value names are the one kind of name that modellers routinely write with spaces and punctuation (`Hp 0`, `PZB/LZB`), so a name-only value is made safe before it is minted: a character is kept when it is a letter or digit of any script or one of `-`, `.`, `_`, `~`, and every other character becomes `_`. Only the IRI changes; the label is the name as written. Names of classes, attributes and enumerations are minted as written.
- **Value IRI conflict** (`EnumerationValueIRIConflict`) — two values of one enumeration whose names differ but whose IRIs are the same, as `Hp 0` and `Hp_0` are. The one built second is refused, because one individual carrying two labels would silently lose a value. A value that shares a name or curie with an existing one is the same value and is merged, not refused.
- **Classifier namespace** — classes and enumerations share one namespace, as classifiers do in a UML package. A name or curie a class already holds cannot identify an enumeration, and one an enumeration already holds cannot identify a class (`ClassifierKindConflict`). Both identity builders check, so the rule holds whichever source is read first.
- **Supported data type** (`SupportedDataType`) — the closed enum of XSD/RDF/RDFS datatypes admissible as attribute types, keyed by their curie literal (e.g. `xsd:string`, `rdf:langString`).
- **Cardinality** (`UMLCardinality`) — a non-negative integer or the unbounded marker `*` (`UMLInfinite`). A blank cardinality is *unspecified* and defaults to 1, per the UML spec. An unparsable cardinality string also defaults to 1, but is logged as a warning so the modeller can find the typo.
- **Multiplicity** (`UMLMultiplicity`) — a min and max cardinality pair, default `[1,1]`. Invariant: max ≥ min, where `*` is greater than any integer, and an unbounded min is never admissible. The constructor is private, so `apply` is the only way to build one and the invariant cannot be sidestepped — a case class would otherwise hand out a synthesized constructor that bypasses the check.
- **Unusable multiplicity** — a pair that breaks the invariant, either as `[*, n]` or as a max below its min. It costs the attribute its *cardinality restriction*, not its existence: the pair falls back to `[0,*]`, which asserts nothing about cardinality, and the attribute keeps its type, label and definition. Reported as `UnboundedMinMultiplicity` or `MaxBelowMin`. Repairing to the nearest valid pair is deliberately rejected — that would assert a constraint the modeller never wrote, and a wrong exact cardinality can make otherwise sound instance data inconsistent, whereas asserting nothing is merely weaker than intended.
- **Generalization set** (`UMLGeneralizationSet`) — the set of child classes sharing one parent, qualified by a *covering constraint* and a *disjoint constraint*.
- **Covering constraint** — `Complete` (the children exhaust the parent) or `Incomplete`.
- **Disjoint constraint** — `Disjoint` (children are pairwise disjoint) or `Overlapping`.
- **Builder-and-cache pattern** — model objects are constructed through builders, and every `build` writes the object into a global mutable cache (`ClassCache`, `ClassIdentityCache`, `AttributeCache`, `AttributeIdentityCache`). The caches, not reader return values, are the hand-off point to the writer. No cache keeps a builder beside the object. `ClassCache` keeps only the classes: *two-pass parent population* (see the reader context) builds a parent again with only its identity and its generalization set, and the *class merge* combines that with the parent as read so far. `ClassIdentityCache` keeps only the identities: a generalization set resolves a child by building an identity from the one half it was given, and the build returns the identity the cache holds for that half. The attribute caches keep only the objects: nothing extends an attribute after it is built, and *enrichment* merges attributes in the cache itself. `EnumerationCache` keeps no builders for the same reason: *enumeration enrichment* merges in the cache, so there is nothing to fetch, extend and rebuild. It does keep where each enumeration was declared, so that an enumeration found to have no values after every input is read can still be reported against its source.

## Invariants and assumptions

- A class belongs to at most one generalization set — a simplifying assumption; UML allows several (`@Todo` in `ClassBuilder`).
- Generalization set names are not yet supported.
- Each half of an enumeration's or a value's identity is judged on its own: a name with a colon or a curie with an unconfigured prefix is an error even when the other half is fine. Class and attribute identities do the same for the curie: one that cannot be expanded is `UnresolvableCurie` even beside a usable name, because keeping the class or attribute under its name alone would give it another IRI than the one asked for without saying so. They are still more lenient for the name: a name with a colon beside a usable curie is dropped without comment.
- Every identity must have a name or a curie. Builders and caches throw a *coded model exception* (see the reader context) rather than a bare `IllegalArgumentException`, so a reader can report which rule was broken: `BlankIdentity` when neither half was given, `NameContainsColon` when a name was used where only a curie could go, `UnresolvableCurie` when a curie's prefix was never configured.
- A bare `IllegalArgumentException` is reserved for programming errors rather than bad input — a generalization set built before its children, a blank literal reaching the writer. Those degrade to a `RowRejected` diagnostic, which is the right outcome for a fault the modeller cannot act on.
- The default covering/disjoint constraints are {incomplete, overlapping} everywhere (`UMLGeneralizationSet`, `GeneralizationSetBuilder`, and the XMI reader's internal representation), matching the UML spec defaults of `isCovering = false` and `isDisjoint = false`.

# Context: reader

Turning input representations of a UML class diagram into cached model objects. A reader never returns model data — it populates the global builder caches in the model context as a side effect, returning only *diagnostics* — and `Main` decides which readers run and in what order.

## Glossary

- **Reader** (`UMLClassDiagramReader`) — the contract `parseUMLClassDiagram(input: InputParameters): Seq[Diagnostic]`: parse one input format, populate the model caches, and report what could not be honoured. The two implementations are `TSVReader` and `XMIReader`.
- **TSV input** — tab-separated files with fixed, named header columns. The *classes file* (`-c`) has columns Name, Curie, Definition, Parents; the *attributes file* (`-a`) has Class, Curie, Name, ClassEnumOrPrimitiveType, MinMultiplicity, MaxMultiplicity, Definition. A cell may be empty; Name and Curie are the two halves of an identity (see *enrichment* in the model context).
- **Parents column** — `|`-separated list of parent identifiers (names or curies) in the classes TSV. Each listed parent acquires the row's class as a child in its generalization set.
- **ClassEnumOrPrimitiveType** — the attribute-type column; resolved via the model's attribute-type resolution order (datatype curie, known class, curie, placeholder class). A blank cell leaves the attribute *untyped* rather than rejecting it, and is reported as a `BlankAttributeType` warning — the tool cannot tell a modeller converting a finished diagram, for whom this is an omission, from one drafting an ontology through UML, for whom it is a legitimate intermediate state, so it accepts the attribute and says something.
- **Class built on the fly** — a class that is referenced without ever being declared, either as a parent in a `Parents` column or as the owner of a row in the attributes TSV. Both are built as full classes, so which file first mentioned a class does not change what it is: it is labelled, and it counts towards global disjointness like any declared class. It differs only in having no definition, because nothing ever supplied one. An attribute's owner is built *after* the attribute succeeds, so a rejected row leaves no class behind — a row we refused is not evidence that its owner exists.
- **Enumerations input** — CLI flags (`-e`, `-n`) and header enums (`EnumerationsHeader`, `EnumerationValuesHeader`) exist, but enumeration parsing is not implemented yet.
- **XMI input** — an Enterprise Architect XMI export (`-m`), parsed with DOM + XPath. Classes come from `packagedElement[@type='uml:Class']`; class definitions, attributes (with type, bounds, and documentation) come from EA's `<element>` extension section; covering/disjointness comes from the `generalizationSet` node's `isCovering`/`isDisjoint` attributes.
- **Two-pass parent population** — pass one reads all classes/rows, building each class and collecting a parent→children map; pass two (`populateParentsWithTheirChildren`, in `ReaderHelper` for TSV and inlined in `XMIReader`) fetches each parent's cached builder, attaches its generalization set, and rebuilds it. A parent referenced but never declared as a class is built on the fly.
- **Generalization set merge rule** (XMI) — generalizations pointing at the same parent are merged into one generalization set only if their covering/disjoint flags agree; a mismatch is an error.
- **Override precedence** (`--overrides`, `Overrides` enum) — when both TSV and XMI are provided, the overriding source is parsed *last*, so its values win during cache enrichment while empty fields inherit from the earlier source. Default: TSV overrides XMI.
- **Row-level error handling** — a row that fails to parse is recorded as a *diagnostic* and skipped; parsing continues. There is no fail-fast mode, so one malformed row never costs the modeller the rest of the file.
- **Diagnostic** — a returned record of something that could not be honoured, carrying a *severity* (a warning means a default was substituted, an error means something was dropped), a stable *code*, an optional *source location* (file and row, numbered as file lines so the header is row 1), and a human-readable message. `parseUMLClassDiagram` returns `Seq[Diagnostic]` rather than `Unit`: this is a deliberate exception to the caches-as-hand-off rule, because a caller that cannot see what was rejected cannot react to it. Callers match on severity and code; message wording is not part of the contract.
- **Coded model exception** (`UMLModelException`) — the exception model builders throw when input cannot become a model object. It carries the diagnostic code, so a reader catching it reports precisely what was wrong instead of degrading every failure to a generic rejected row.

## Invariants and assumptions

- Readers communicate exclusively through the model caches; order of reader invocation is therefore semantically significant.
- The TSV format has no columns for covering/disjoint constraints — generalization sets from TSV always get the UML spec defaults {incomplete, overlapping}. Only XMI input can express `Complete`/`Disjoint` variations.
- XMI parsing depends on Enterprise Architect's export dialect (the `<element>` extension section); XMI from other tools is untested.
- `parseClassAttributes` in `TSVReader` is covered by the attribute-type, multiplicity and prefix case groups in the test context; it is no longer unverified.
